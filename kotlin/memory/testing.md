
- **Проверка логов отправки медиа, альбомов и персистентности удаления**:
  ```bash
  adb logcat -d | grep -iE "AndroidImageMessageSender|AndroidVideoCircleSyncCoordinator|FLOW_TIMELINE|DirectChatStateHolder|RoomDirect|VoiceMediaCache"
  ```
- **Проверка выделения альбомов долгим тапом по фото**:
  Долгий тап на любую ячейку фото (`SingleImageCell` / `ChatAlbumBubble`) в обычном режиме чата переводит экран в режим селекшна и выделяет весь альбом (`toggleMessageSelection`). В режиме селекшна простой тап по ячейке/чекбоксу точечно переключает выбор отдельного фото.
- **Проверка мгновенных превью и кэша аудио (Telegram Parity)**:
  - Фотографии: проверить отсутствие белых/серых вспышек и моргания при загрузке — микро-превью `data:image/jpeg;base64,...` мгновенно отображается как плейсхолдер в `AsyncImage` с `blur(6.dp)` и плавно сменяется оригиналом.
  - Голосовые сообщения: при воспроизведении входящего сетевого голосового данные оседают в `voice_media_cache` (128 МБ `SimpleCache`), при повторном воспроизведении или в режиме самолёта звук играет мгновенно из локального кэша.
  - Видеокружки: исходящие кружки генерируют `TinyThumb` 24x24 px прямо из файла без долгого отдельного S3 аплоада thumbnail.
  - Автозагрузка и экран «Данные и память»: в профиле открыть раздел «Данные и память», проверить переключение пресетов и тумблеров сетей. При получении новых сообщений проверить работу `MediaDownloadManager` и подсчет/очистку кэша.
  - Проверка viewport-автозагрузки (Telegram Parity): при открытии чата с очищенным кэшем скачиваются ТОЛЬКО видимые на экране фото (не вся история из базы Room). При прокрутке вверх/вниз в очередь автозагрузки поступают появляющиеся во вьюпорте ячейки.
  - Проверка паузы фоновых автозагрузок при ручном скачивании: при клике пользователя по кнопке скачивания на любой картинке фоновые фоновые автозагрузки мгновенно приостанавливаются, пока не завершится приоритетное скачивание.
- **Проверка отображения и радиального прогресса скачивания медиа (Telegram-style)**:
  - При получении или наличии фото без локального кэша отображается размытое микро-превью (`blur(14.dp)`) и статичная кнопка 48dp со стрелкой Telegram (`TelegramDownloadIcon`) и точным размером файла (например, `1.8 МБ`). Никакого паразитного вращения вхолостую.
  - Тап по кнопке стартует скачивание через `MediaDownloadController.enqueue(...)`: стрелка сменяется на крестик (`TelegramCancelIcon`), радиальное кольцо прогресса заполняется по мере загрузки.
  - При нажатии на крестик скачивание отменяется через `MediaDownloadController.cancel(...)`, статус возвращается в `Idle` / `Failed`.
  - При завершении скачивания кнопка исчезает, фото четкое. При тапе открывается `FullscreenImageViewerV2` с локального файла на диске.
  - В «Данные и память» при нажатии «Очистить кэш» полностью стираются файлы, кэш Coil (`SingletonImageLoader`) и сбрасываются стейты менеджера (`MediaDownloadController.resetAll()`).

- **Проверка чтения сообщений и статусов (Telegram Parity)**:
  - При быстром скролле чата сетевые запросы дебаунсятся на 3 секунды. Проверить по логам: сетевой `read-up-to` отправляется один раз с максимальным `messageId`, без спама запросами на каждое сообщение.
  - При выходе из чата до истечения 3 секунд (`dispose()`) отложенное чтение мгновенно сбрасывается (`flush`).
